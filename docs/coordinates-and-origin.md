# VAB 坐标、动作表规范化与锚点设计

状态：动作表的初始根平移规范化已于 2026-09-22 实施；人工语义锚点和舞台适配仍是后续设计。VAB 仍为发布前版本 1。

## 坐标基础

SWF 根时间轴使用 Flash 坐标：X 向右，Y 向下。根坐标 `(0, 0)` 通常对应舞台左上角，但它不自动表示人物脚底、身体中心或其他游戏语义位置。

MovieClip/Sprite 的局部 `(0, 0)` 是元件注册点。元件内容可以位于注册点周围任意位置；父级 PlaceObject 矩阵把注册点映射到父空间。Animate 中可移动的旋转/缩放中心在导出后已经合并进仿射矩阵，SWF 不提供一个可直接当作角色锚点的独立值。

可见内容 bounds 也不是锚点。姿势、皮肤、拖影和滤镜都会改变 bounds；逐帧根据 bounds 居中会产生抖动。bounds 只适合预览 framing、裁剪和可见性判断。

运行时渲染把 Flash 的 Y 向下转换为 Bevy 的 Y 向上：

```text
BevyWorld = EntityTranslation + (VabLocal.x, -VabLocal.y) * EntityScale
```

渲染器不根据相机、视口或 bounds 追加隐式平移。旧版 `bevy_flash` 在 Shader 中还把相机中心映射到 Flash 舞台左上角；新版把 VAB 当作可放入世界场景的独立实体，因此不采用与视口绑定的舞台偏移。

## 已实施：带标签动作表的逐动作源布局规范化

有些合并 SWF 是动作素材表：根时间轴的每个动作段只放置一个控制子 MC，不同动作被摆在 Flash 舞台的不同位置。`123620.swf` 就属于这种结构。如果直接保留根 PlaceObject 平移，切换动作会把角色移动到素材表中的另一个位置。

编译器现在使用以下明确契约：

- 根时间轴中除 `event_` 外的每个标签都定义动作；
- `anim_xxx` 仍受支持，运行时名称为 `xxx`；其他标签保留原名；
- 第一个动作标签必须从根帧 0 开始；
- 每段动作的每个根帧至多有一个根级控制对象；
- 取该段首个非空帧中控制对象的 PlaceObject 平移 `(tx, ty)`；
- 对该动作所有帧的整棵烘焙结果统一左乘 `Translate(-tx, -ty)`；
- 空动作没有可抵消的平移，使用 `(0, 0)`；多个根对象含义不明确，编译失败；
- 完全没有动作标签的 SWF 是普通场景，仍生成 `default`，允许多个根对象且不自动平移。

公式为：

```text
clip_origin = first_non_empty_root_object.translation
normalized_point(frame) = original_point(frame) - clip_origin
```

这是每段动作一次性的固定平移，不是逐帧归零。它保留：

- 控制对象原有的缩放、旋转和斜切；
- 子元件内部的注册点和所有嵌套变换；
- 后续帧相对于动作首个非空帧的根运动；
- 滤镜、遮罩、混合和皮肤结构。

例如首帧根平移是 `(100, 40)`，后一帧是 `(112, 35)`，烘焙后分别是 `(0, 0)` 与 `(12, -5)`。动作内部的 12/-5 位移仍然存在，所以不会因为规范化而冻结根运动。

这条规则不读取图形 bounds，因此不会随姿势变化产生帧间抖动。它解决的是“不同动作在素材表上摆放位置不同”，而不是自动猜测脚底。

## 已验证素材

`spirit2159src.swf` 的多个动作原本使用同一个根平移，规范化后继续相互对齐。

`123620.swf` 的动作根平移明显分组，例如 IDLE 约为 `(149.10, 227.85)`、多个战斗状态约为 `(2034.30, 2122.50)`、ATTACK 约为 `(930.10, 430.80)`。逐动作抵消后，常规身体状态回到相近的局部范围；APPEAR、ATTACK 和魔法动作的内部进入/攻击位移仍然保留。

同目录的 `123620-idle.swf` 已经是单独提取并接近零平移的状态素材。这说明原游戏资源流程很可能会提取/实例化状态符号或额外应用状态偏移，而不是把合并素材表的舞台坐标直接当作游戏世界坐标。这是根据现有文件作出的推断。

`wu_kong.swf` 没有根动作标签，根帧含多个对象。它按普通场景处理，不触发动作表限制，换肤结构和原坐标保持不变。

## 与已正确对齐素材的边界

不同动作元件的注册点可以不同，父 PlaceObject 平移也可能是在补偿这些注册点：

```text
待机：脚底局部位置 0  + 根放置 300 = 根空间脚底 300
攻击：脚底局部位置 50 + 根放置 250 = 根空间脚底 300
```

如果这种 SWF 已经把所有动作正确对齐到一个公共根空间，逐动作抵消不同的根平移会删除作者的补偿。当前实现因此不是对任意 SWF 的启发式修复，而是带动作标签输入格式的一部分：标签动作段被视为独立摆放的动作素材。已经具有公共语义原点的素材应在导入前统一外层布局，或未来使用显式导入模式。当前测试中的 spirit 素材各动作根平移相同，不存在该冲突。

不能使用以下方法替代当前规则：

- 每帧重新计算偏移；
- 根据当前皮肤改变偏移；
- 修改嵌套子 MC 的局部注册点；
- 使用第一帧完整矩阵的逆矩阵，进而删除作者的缩放或旋转；
- 根据逐帧 bounds 自动移动实体。

## 后续：跨资源共享的语义原点

逐动作规范化让同一动作表中的片段落回各自局部原点，但它不能凭图形推断“脚底中心”。若两个 VAB 需要在同一个 Bevy `Transform` 下可互换，它们仍需共享同一种语义原点。

推荐的显式约定是在动作制作流程中提供 `anchor_origin`，由素材作者把它放在脚底中心、身体中心或特效中心。编译器读取锚点在对应动作根空间中的位置，把它作为明确的语义偏移，并从渲染节点中移除辅助实例。实施前需要验证空 MovieClip 和实例名称能稳定导出，并确定它与当前动作段源布局偏移的组合顺序。

计划校验：

- 每段动作最多一个 `anchor_origin`；
- 锚点位置在该动作内保持不变；
- 锚点不携带会混淆原点含义的缩放、旋转或斜切；
- 缺失锚点时可使用显式导入配置，不能通过 bounds 猜测脚底；
- 动态挂点如 `anchor_hand`、`anchor_weapon` 保留逐帧动画位置，不参与根原点规范化。

采用共同约定后：

```text
角色 A 的 anchor_origin = 脚底中心
角色 B 的 anchor_origin = 脚底中心
```

两份资源使用同一个实体 Transform 时，脚底才能可靠落在同一世界位置。若一个资源以脚底为原点、另一个以头顶为原点，编译器无法仅根据画面自动判断并修复。

## 舞台资源与实体动画

完整 Flash 场景或 UI 画布通常需要保留舞台左上角语义，并通过相机/视口执行 contain、cover 等适配。人物、怪物、投射物和特效等 Spine 式独立实体适合动作表规范化与语义锚点。未来如保存 SWF `stage_size`，舞台适配应作为显式辅助 API，不能改变独立实体的默认世界坐标规则。

可继续增加以下只读或纯计算 API：

- SWF 舞台 bounds；
- 每个 clip 全部帧的联合 content bounds；
- 基于固定 bounds 的预览居中、contain、cover 和相机 framing；
- 查询编译时采用的动作源布局偏移及其来源；
- 查询显式动态挂点的逐帧位置。

`examples/show_demo.rs` 为展示资源而抽样若干帧计算内容范围并调整实体和相机。这属于示例层 framing，不是正式锚点算法，也不能保证覆盖动画全部视觉极值。

## 验收结论与后续测试

当前实现已经通过编译器单测，覆盖无前缀动作标签、`event_` 排除、`anim_` 兼容、逐动作固定平移、根运动保留、多根对象报错，以及无标签普通场景保持原样。所有示例 VAB 已用新编译器重新生成，VAB 版本保持 1。

后续人工语义锚点实施时仍需验证：

- 待机、攻击、受击和死亡使用同一语义点切换时不跳位；
- 暂停、播放、换片段和换肤不改变实体原点；
- 1×/2× 缩放围绕期望原点；
- 两个采用相同 `anchor_origin` 约定的 VAB 替换后保持世界定位；
- 无锚点或结构不明确的资源不会被 bounds 启发式静默移动。
